# SSR-PPT-SKILL

把需求、证据、叙事结构、逐页策划和视觉制作分开处理，交付观众能理解、用户能继续修改的演示文稿。

## 执行与交互

- 使用用户已经提供的受众、目的、资料、总页数、品牌、模板和格式，不重复询问。读取已有文件只为完成当前任务。
- 需求足以制作时，说明必要假设后连续完成资料整理、大纲、策划、制作、验收和交付。大纲和策划稿是保存的中间产物，不是强制确认关卡。
- 只有缺失信息会实质改变结果时提问，例如受众与用途无法推断、要求引用但缺少关键数据、指定模板尚未提供。集中询问，继续不依赖答案的工作，不把等待当作批准。
- 页数、一般风格等可推断事项由 Codex 判断；精确的 N 页包含封面与结束页，不额外添加。用户指定“只看大纲”“先给样稿”时止于该阶段。
- 用户未指定格式时默认交付 HTML 和 PPTX；用户只要一种时仅制作该格式。两种格式使用同一策划稿和数据，不承诺转换后逐像素一致或保留 HTML 动画。
- 默认由当前 Codex 完成，不强制调用 Gemini、Grok、Claude CLI 或子智能体。Inner Web Brain / Web Brain 仅在用户为当前任务明确要求时使用。
- 只做本地制作和验证。遵守现有授权与依赖约束，不部署、不推送，不覆盖未授权的原文件。

## 1. 建立需求与证据

把主题、受众、演示目的、关键内容、篇幅、视觉约束和交付格式记入策划稿开头；保持简短。

优先整理用户提供的资料。只有任务需要外部事实、时效信息或用户要求检索时才研究，使用当前环境可用的搜索与阅读工具，不绑定某一家服务。数字保留单位、时间、口径和来源；区分事实、计算结果、假设与建议。不能把缺失资料补成确定事实。

有外部资料时保存 `sources.md`，用简短来源标识关联到相关页面和 PPTX 备注；HTML 中也提供可找到的来源链接。无需为纯用户材料重复建立搜索流程。

## 2. 大纲与策划稿

读取 [references/planning.md](references/planning.md)。先决定每页的目的和顺序，再做视觉设计。报告与说服场景适合结论先行；教学或故事按理解顺序组织，不强套目录和金字塔结构。

必须保存逐页 `planning.md` 并随成品交付；一页任务用短版，已有文稿修改只更新受影响页面。策划说明核心信息、依据、内容层级、版式意图与可编辑对象，不能只有页标题或笼统风格词。无需生成额外策划 PPT 文件，除非用户要求。

## 3. 定义视觉方向

先遵循用户模板、品牌或参考。没有参考时选少量字体、颜色和间距，保持全套一致；中文字体须确认可用，字号以最终显示尺寸检查。

由内容选择版式：比较用并列、趋势用图表、过程用流程、观点用大字或图片。Bento 卡片可用于组织有明确关系的信息，用面积与位置表达主次；不要把每页都做成相同卡片网格。交替安排密集页和简洁页，避免连续重复布局。

重要内容放在安全区域内，优先缩减与拆分内容来解决拥挤，再考虑字号。保留观众需要的数字、标签和结论依据。摄影、插画等按任务需要使用真实素材或可用的图像生成工具；不为装饰堆砌无关图片。

## 4. 制作交付格式

- **HTML**：读取 [references/html.md](references/html.md)。默认单文件离线可打开，支持键盘与按钮翻页、页码、全屏和打印。可复用 `assets/player.css` 与 `assets/player.js` 并内联进成品；它们只负责播放器，不限定页面视觉。
- **PPTX**：读取 [references/pptx.md](references/pptx.md)。在 Codex 桌面优先复用已安装的官方 presentations 工具和 bundled runtime；其他环境使用已安装且适合当前项目的原生 PPTX 工具。正文、表格、数据图表及要求可编辑的示意图使用原生对象。
- **两者都要**：共享页数、顺序、核心文字、数据与视觉规则，分别制作和验收。可以复用结构化页面描述，不把 HTML 截图或整页 SVG 塞进 PPTX 当作可编辑交付。

## 5. 实际预览验收

**生成文件、解析成功、代码检查和模型评分都不能替代实际预览。**

1. 对照策划稿检查内容覆盖、总页数、事实、单位和引用；移除未解决的占位与制作过程文案。
2. HTML 用浏览器实际打开最终文件，等待字体与图片加载，逐页查看，测试翻页按钮、方向键、边界页、全屏（环境支持时）与打印。检查浏览器控制台与资源失败，确认无本次引入的错误。检查常用宽屏和较小视口，保证页面能完整查看。
3. PPTX 导出后重新读取最终文件并逐页渲染；逐张查看完整尺寸图像。缩略图仅用于整体节奏。检查重叠、截断、字体、图表标签与数据、图片比例和模板一致性。
4. 检查 PPTX 原生对象及图表数据，排除全页图片伪装。使用测试副本修改代表性文字、表格单元格和图表值，保存、重新打开并渲染，确认变化生效。无需在每个最终文件中留下测试改动。
5. 发现本次引入的问题就修复，重新导出并检查受影响页面；全局字体或主题改变时重新查看全套。两种格式各自通过才算双格式完成。

如果缺少浏览器、渲染器或必要的导出能力，保留已完成产物，明确指出哪个验收项尚未完成；不得静默改成交付整页图片，不得声称已完成实际预览。只有确实在 PowerPoint 中打开和操作过，才报告 PowerPoint 实机验证。

## 6. 交付

交付用户所需的 `index.html`、`deck.pptx` 与 `planning.md`，研究过则附 `sources.md`。名称可按主题调整。生成源码、截图和验收记录留在私有构建目录；用户要求时再交付。保持策划稿与最终版本一致。

简短说明完成的格式和使用方式，提供真实绝对路径链接；如有影响使用的限制，准确说明。展示成品有帮助时用 Codex `open_in_codex` 打开 HTML。打开面板不能算完成预览验收。达到当前要求后停止。
